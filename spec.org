This spec is a *reading and grading instrument*, not merely a bootstrapper. It
states one core pattern, the *structure taxonomy* that says how each class is
soundly projected, the *eventing interview* probes and rubric, the challenge->
concept map, and the interview flow. The picker (=aygp-dr/picker-state-projection=)
is the reference /chain/ instance; §1 is kept verbatim from it, and everything
after generalizes it.

* 1. The core pattern (kept verbatim from the picker)

Every challenge is the same three artifacts and one claim.

| role              | what it is                                       | property                     |
|-------------------+--------------------------------------------------+------------------------------|
| *source of truth* | append-only log, ordered, one row per event      | the only thing you may trust |
| *derivation*      | a /pure function/ log -> view                      | replay = reprocess = rebuild |
| *view*            | a lossy, convenient projection of the log         | derived; never authoritative |

The deep FP statement, portable to every instance: the derivation is a
*catamorphism over the free monoid on events* - a pure function =[Event] ->
View=. So "same log, same view" is *referential transparency*, not something you
enforce; *replay*, *reprocessing*, and *rebuild* are all "apply the same pure
function to the same list." A state machine is therefore *a deterministic
function of its log* - the sentence the whole ladder turns on, and the sentence
Raft (§2.7, challenge 09) makes fault-tolerant.

The picker is the simplest instance: a *chain*, whose view is a set of wide state
flags. The claim there - "the wide-flag view is broken, and only some defects
survive a clean rebuild" - is exactly what the taxonomy below generalizes. For
most structure classes *the wide-flag view is not even sound*, and choosing the
right projection is half of each challenge.

* 2. The structure taxonomy

For each structure class S we state (a) what a *valid projection* is, (b) whether
the *wide-flag projection is SOUND*, (c) the *right projection* when it is not,
(d) the *invariants* that apply. The wide-flag view (one boolean column per
state, downward-closed) is the picker's view; it is the special case, not the
general one.

Two order-theoretic notions carry across the whole table:

- *down-set (order ideal)*: a set that is downward-closed under S. The picker's
  I1 (predecessor-closure) + I2 (non-empty) are exactly "the flag-set is a
  non-empty down-set of the chain."
- *soundness vs completeness* of the wide-flag view: /sound/ = every row the view
  emits is a valid element of S (a real down-set); /complete/ = a valid row
  determines exactly one current state. On a chain both hold; the ladder walks
  the classes where one or both break.

** 2.1. Chain - total order

- *Instance*: challenge 01 order-lifecycle (=placed < paid < shipped <
  delivered=); the picker (=received < picking < picked < packed=).
- *(a) valid projection*: a non-empty *down-set* of the chain - wide flags,
  downward-closed.
- *(b) wide flags SOUND?*: *yes*, and complete. This is the one class where the
  picker's whole apparatus applies unchanged.
- *(c) right projection*: the wide flags themselves.
- *(d) invariants*: schema gate (I3 domain, I4 arity, I5 unique key) checked
  /before/ the structure gate; structure gate I1 predecessor-closure + I2
  non-empty = down-set; the *unobservable* I6 = arrival order agrees with
  event-time (a straggler check - the one property the view forgets).

** 2.2. Cycle / reversible graph - NOT a poset

- *Instances*: challenge 02 traffic-light (3-cycle =red->green->yellow->red=);
  challenge 04 lamp-two-switch (the Boolean lattice ={0,1}^2= as a strongly-
  connected reversible graph); challenge 03 elevator (a large /product/ automaton
  with a request set - same lesson: not a chain, not acyclic).
- *(a) valid projection*: the *current state* in the (finite) state set, plus a
  transition-legality assertion over consecutive events.
- *(b) wide flags SOUND?*: *no - UNSOUND*. A state is re-enterable, so the flag
  set loses multiplicity and admits non-paths; antisymmetry fails (a preorder,
  not a partial order), so there is no down-set characterization to project onto.
  This is the *refutation case*: it is what breaks the picker's view.
- *(c) right projection*: =current_state= (the single current node) + a
  *transition-legality* check that every consecutive pair is a legal edge, + any
  state predicate (lamp: =On iff both switches on=; elevator: doors closed while
  moving, never skip a requested floor, no reverse with requests the current way).
- *(d) invariants*: schema gate as in 2.1; *T-legality* (every step is an edge of
  S - an /illegal transition/); the state predicate; I6 arrival-vs-event-time;
  unknown-state and duplicate-delivery as schema-level defects.

** 2.3. Containment poset / tree - down-sets generalize

- *Instance*: challenge 05 login-hierarchy (leaves =LogOut, Main, Settings,
  Report1, Report2=; containment =LogIn contains {Main, Settings, Reports}=, =Reports contains
  {Report1, Report2}=; a *tree* = genuine poset), with a /cyclic navigation graph/
  laid over the tree.
- *(a) valid projection*: a *flag per ancestor*, downward-closed on the tree - the
  set of active nodes is an *order ideal* (ancestor-closure: a node's flag implies
  its parent's). This is the picker's down-set, lifted from a chain to any poset.
- *(b) wide flags SOUND?*: *yes* (a tree is a DAG; ancestor-sets are valid down-
  sets), but *not complete on its own*.
- *(c) right projection*: the ancestor-closed flag set; for completeness add the
  *one-leaf rule* - =TopDown[state] = {}=, i.e. exactly one active leaf pins the
  current state.
- *(d) invariants*: schema gate; ancestor-closure (down-set on the tree); the
  one-leaf completeness rule; transition-legality on the navigation graph (which
  is cyclic even though containment is not); I6.

** 2.4. DAG - branching lifecycle (soundness/completeness theorem)

- *Instances*: the branching variants - a =rolled_back= branch on a deploy chain;
  any lifecycle that forks. (Named here as the general case between 2.1 and 2.3;
  the picker README states the theorem, and challenge 05's tree is the acyclic
  witness.)
- *(a) valid projection*: a down-set of the DAG (reachable-from-root, topologically
  consistent).
- *(b) wide flags SOUND?*: *sound but not complete*. This is the *soundness/
  completeness theorem*: on a DAG every emitted row is still a valid down-set
  (soundness holds), but a valid row no longer determines one current state
  (completeness fails - two branch tips are both valid).
- *(c) right projection*: the down-set /plus/ an explicit =current_state= column to
  restore completeness (make the fork observable).
- *(d) invariants*: schema gate; acyclicity + reachability (the DAG condition);
  down-set; the completeness caveat asserted as a test; I6.

** 2.5. DFA / finite automaton - the view collapses to accept/reject

- *Instance*: challenge 06 dfa-even-01 (even #0s and even #1s; states =EE, EO, OE,
  OO= = parity x parity; complete, cyclic; start & sole accepting state =EE=).
- *(a) valid projection*: a *single boolean* - =accept/reject= (is the final state
  accepting?).
- *(b) wide flags SOUND?*: N/A - the automaton is cyclic, so wide flags are unsound
  as in 2.2; but the natural view collapses further, to one bit.
- *(c) right projection*: run the fold to the final state, then test membership in
  the accepting set. The *fold IS delta\**, the extended transition function - a
  catamorphism over the free monoid on the alphabet (§1). Completeness is /total/:
  every string maps to exactly one state.
- *(d) invariants*: schema gate = alphabet membership (unknown symbols); the fold
  is total and deterministic; optionally the state trace; I6 if symbols are
  timestamped.

** 2.6. Pushdown / register machine - state is (control, stack)

- *Instances*: challenge 07 lr-parser-fsm (an LR(0) automaton, states =0..8=,
  accepting ={0,3,4,8}=, self-loops and back-edges -> cyclic, /needs a stack/);
  challenge 08 register-machine (SICP §5.1 controller over a datapath: GCD is a
  loop, factorial is a loop + a stack).
- *(a) valid projection*: for the parser, the *parse outcome* (accept iff at an
  accepting control state with empty input) + a shift/reduce trace; for the
  register machine, the *register file at =done=*.
- *(b) wide flags SOUND?*: *no* - a finite-state view is insufficient. The "state"
  is =(control state, stack)=; shift pushes, reduce pops. This is *beyond finite-
  state*: the datapath/stack makes the controller Turing-powerful.
- *(c) right projection*: fold the token/instruction stream through =(control,
  stack)=; project the outcome (parse result / final registers). Report stuck or
  illegal transitions, reads of uninitialized registers, and *stack imbalance*.
- *(d) invariants*: schema gate; transition-legality on the control automaton;
  stack balance (pushes/pops reconcile); no read-before-write on registers;
  termination at an accepting/=done= state.

** 2.7. Replicated state machine - the unifier

- *Instance*: challenge 09 raft-replicated-sm (roles =follower -> candidate ->
  leader=, reset to =follower= on higher term; the *replicated log* is the source
  of truth; each node =apply=s the committed log to derive state).
- *(a) valid projection*: two folds - (i) the role FSM over election/heartbeat
  events (a cycle, §2.2); (ii) the *replicated state machine* =apply(committed_log)
  -> state=. The projection of interest: *every replica's derived state agrees*.
- *(b) wide flags SOUND?*: the role FSM is a cycle (unsound wide flags); the applied
  state machine is whatever S the application is - the point is not the shape but
  the *replication*.
- *(c) right projection*: replicate the *log*, then =apply= it deterministically;
  two nodes with the same committed log reach the same state. This is §1 made
  fault-tolerant.
- *(d) invariants*: log agreement (same committed prefix => same state - the
  determinism assertion); role-FSM transition-legality; term monotonicity;
  commit-before-apply ordering.
- *Why it unifies*: "a state machine is a deterministic function of its log." Every
  class above (chain, cycle, poset, DAG, DFA, pushdown, register machine) is a
  *single-node instance* of what Raft replicates. The whole ladder is one problem;
  09 is why.

** 2.8. Taxonomy at a glance

| class (§)        | valid projection                 | wide flags sound?      | right projection when not          |
|------------------+----------------------------------+------------------------+------------------------------------|
| chain (2.1)      | non-empty down-set               | yes + complete         | (wide flags)                       |
| cycle/graph (2.2)| current state + T-legality       | *no - unsound*         | current_state + transition check   |
| poset/tree (2.3) | ancestor-closed set (down-set)   | sound, not complete    | down-set + one-leaf rule           |
| DAG (2.4)        | down-set of the DAG              | sound, not complete    | down-set + current_state column    |
| DFA (2.5)        | accept/reject (one bit)          | n/a (cyclic; collapses)| fold = delta*, test accepting set      |
| pushdown/reg (2.6)| (control, stack) -> outcome      | *no - beyond finite*   | fold through (control, stack)      |
| replicated (2.7) | apply(committed_log); replicas agree | n/a (unifier)      | replicate log, apply deterministically |

* 3. The eventing interview dimension

The taxonomy grades the /structure/. This section grades the /eventing/ - event
sourcing and streaming - because the same log->derivation->view shape is where
every one of these concepts /bites/. Each probe below names the concept, where it
bites in the ladder, and what a strong answer looks like. The rubric (§3.2)
weights the signals, generalizing the picker README's rubric.

** 3.1. The probes (concept -> where it bites -> strong answer)

| # | concept                          | where it bites                                          | strong answer                                                                 |
|---+----------------------------------+---------------------------------------------------------+-------------------------------------------------------------------------------|
| E1 | *log as source of truth*         | all challenges; the wide view is never authoritative     | never repairs the view; always names the upstream log and its row shape       |
| E2 | *ordering: arrival vs event-time / processing-time* | I6 in every challenge; traffic-light straggler | distinguishes /event time/ from /processing (arrival) time/; I6 is event-time  |
| E3 | *idempotence & dedup*            | duplicate delivery (picker I5; 02/04 dup event)          | dedup by event key; a re-delivered event must not change the fold's result    |
| E4 | *replay / reprocessing*          | the whole pattern (§1); rebuild-curable defects vanish   | replay = reprocess = rebuild; same log => same view (referential transparency) |
| E5 | *log compaction*                 | chain/DFA (keep last per key vs full history)            | knows compaction is safe only when the fold depends on latest-per-key, not history/order - and that I6 needs history |
| E6 | *exactly-once vs at-least-once*  | 02/04 duplicate; Raft apply (09)                         | at-least-once + idempotent fold ~ effectively-once; true exactly-once needs dedup at the sink |
| E7 | *CQRS: aggregate-validates vs projector-reports* | who rejects an illegal transition | the /aggregate/ (write side) rejects illegal transitions; the /projector/ (read side) only reports anomalies - it must not silently repair |
| E8 | *event-carried state*            | fat vs thin events; register writes (08); AppendEntries (09) | events carry enough state to fold without external lookups; contrast thin notification events |
| E9 | *backpressure / straggler / late arrival* | I6; elevator request bursts; Raft heartbeat timeout | late/straggling events are an ordering fact to surface (I6), not to reorder away; backpressure is a consumer-side concern, not a data defect |
| E10 | *replication / determinism*     | Raft (09); every single-node class is a replica-of-one   | same committed log => same state on every replica; the fold must be deterministic (no wall-clock, no map-iteration order in output) |

** 3.2. Interviewer rubric (signals, weights)

Generalizes the picker README's rubric to the whole ladder. Signals are what to
listen for; weight is how much it moves the needle.

| signal                                                                    | weight | class / concept |
|---------------------------------------------------------------------------+--------+-----------------|
| separates schema failures from structure failures, unprompted             | high   | any             |
| picks the /right projection/ for the class (not wide flags by reflex)      | high   | 2.2-2.7         |
| says the wide-flag view is unsound for a cycle/reversible graph, and why   | high   | 2.2             |
| states valid rows = down-sets, and lifts it from chain to poset/tree/DAG   | high   | 2.1/2.3/2.4     |
| says ordering (event-time) is unobservable in the view, unprompted         | high   | E2              |
| names the upstream log and gives its row shape                             | high   | E1              |
| leaves the irreducible defect broken after rebuild and says why            | high   | E4              |
| the projector /reports/ and the aggregate /validates/ - does not repair    | high   | E7              |
| gives the DAG soundness-but-not-completeness theorem                       | medium | 2.4             |
| adds current_state / anomaly columns to restore completeness               | medium | 2.4/2.2         |
| dedups by event key; a redelivery does not change the fold                 | medium | E3/E6           |
| distinguishes exactly-once from at-least-once + idempotent                 | medium | E6              |
| writes the fold as delta* / catamorphism over the free monoid                  | medium | 2.5/§1          |
| recognizes (control, stack) is beyond finite-state                         | medium | 2.6             |
| checks stack balance / no read-before-write                                | medium | 2.6             |
| states "same committed log => same state" as determinism                    | medium | 2.7/E10         |
| reasons about when compaction is safe (latest-per-key vs history)          | medium | E5              |
| treats late arrival as a fact to surface, not to reorder away              | medium | E9              |
| negative-tests the checker against the broken fixtures                     | medium | any             |
| follows a deliberate structure-class switch by the interviewer             | medium | transfer        |

*Anti-signal (all classes)*: hand-editing the view to "fix" it. In every
vocabulary this is a write that bypasses the log (ES: data not on events; DD:
integrity violation; EM: single-writer violation; MQ: out-of-band write; RA:
bypassing the view definition; OT: a row not in the image of the fold). Surfacing
whether a candidate reaches for it is part of the exercise's design.

* 5. Interview flow

What to hand the candidate, and when to switch structure class to test transfer.

1. *Open on the chain (01 / the picker).* Hand the broken wide-flag view and the
   log. The candidate should separate schema from structure defects, name the log,
   say ordering is unobservable, and leave the irreducible defect broken after
   rebuild. This establishes the shared vocabulary (§1).
2. *Switch to a cycle (02 traffic-light) to test transfer.* The wide-flag view is
   now *unsound*. The signal is whether the candidate /notices/ and reaches for
   =current_state= + transition-legality instead of forcing flags. This is the
   pivot the whole taxonomy is built to expose.
3. *Lift to a poset (05 login-hierarchy).* Down-sets generalize from the chain:
   ancestor-closure. Watch for the one-leaf completeness rule.
4. *Introduce branching (DAG, §2.4).* Elicit the soundness-but-not-completeness
   theorem; a strong candidate adds a =current_state= column unprompted.
5. *Collapse to a bit (06 DFA).* The view is accept/reject; the fold is delta*. Probe
   compaction (E5): what can you throw away and still recompute the answer?
6. *Go beyond finite-state (07 / 08).* The state is =(control, stack)=. Probe
   stack balance and event-carried state (E8).
7. *Close on replication (09 Raft).* Same committed log => same state. This retells
   every earlier challenge as a single-node instance of a replicated machine.

Switch vocabulary (KS/MQ/RA/ES/DD/EM/OT) at any step to test whether the
candidate's model survives re-framing; following a deliberate switch is a rubric
signal (§3.2). A candidate who holds several models shallowly is a stronger signal
than one who holds one deeply.

* 7. Methodology inherited

This spec assumes the operating disciplines in [[./.meta/methodology.org][=.meta/methodology.org=]] and the terms
in [[./.meta/vocabulary.org][=.meta/vocabulary.org=]]. The load-bearing ones: spec-governs (this file is

verifier (each solved challenge pins a byte-exact =examples/oracle-contract.txt=
and negative-tests its checker); run-it-before-believing-it; one editable
representation (shared fixtures under each challenge's =data/=); EDD for anything
speculative (=experiments/NNN-slug/= with a falsifiable hypothesis); PCP
(conventional commits, one step, git notes on spec/oracle/harness changes);
re-tell-not-port (each language example teaches what it frames best). A run that
refutes this spec /amends/ it. To stamp a new challenge from a structure class,
=bin/new-exercise= copies the problem-independent machinery and templates the
problem-specific files (the picker generator's §12, retained as tooling).
