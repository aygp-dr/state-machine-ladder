* Conjecture

*H*: a timed reservation over a resource fits the ladder as one more structure
class, sec 2.9, without touching the sec 1 core pattern:

1. Each of the two machines is a class the ladder already has. The resource
   lifecycle R is a sec 2.2 cycle. The reservation lifecycle V is a sec 2.4 DAG
   with terminals. Both claims can be decided from the edge tables alone.
2. The one genuinely new invariant is interval non-overlap (I7). It is
   cross-entity, a relation between reservations that share a key, so the
   flag / down-set projection cannot express it. The right projection is, per
   resource, the set of live intervals plus both current_state columns plus a
   coupling check.
3. Time enters without breaking the pure fold. Expiry, no-show and overdue are
   events a scheduler writes into the log. The fold stays =[Event] -> View=. Its
   only "now" is the log's own watermark, and it uses that only to report a
   missed deadline, never to synthesize one.

* What would refute it

- The oracle's =structure= section, computed from the edge tables, shows R
  acyclic or V cyclic.
- A planted defect needs a clock argument: some finding cannot be computed from
  the log alone. Gate 4 greps the fold for any clock read.
- The gate cannot tell a wrong log from the right one: a mutant survives.
- The prose and the code disagree about a canonical table. Gate 2 checks every
  row the fold is built from verbatim against =proposed-spec-2.9.org=.

*Result: not refuted* on the supported cell. R computes as cyclic on
={available, in-service, maintenance, out-of-order}= with terminal =retired=. V
computes as acyclic with terminals ={cancelled, completed, expired, no-show}=.
All four gates pass, and all five mutants are killed.

* What could go wrong / known limits

These are stated so they are not mistaken for coverage:
- *Capacity > 1* is not modelled: airline overbooking as a soft bound, or an
  inventory quantity. I7 would generalize from pairwise disjointness to a
  capacity sum.
- *Active or overdue reservations under a fault* have no in-model compensation.
  =reassign= is legal only from =held= / =confirmed=. C2 reports the stranded
  reservation, but the only way to discharge it is the resource returning to
  AVAILABLE. See decision D9.
- *X1 is evaluated at the watermark only*, not at every event. Suppose a party
  event arrives after a missed deadline, such as a =check_in= after the no-show
  window with no =no_show= written. It is accepted, and the booking leaves the
  state whose deadline passed. See decision D8.
- *Class-level admission* (the capacity of a class over an interval) is not
  checked. A class-keyed reservation is checked when it binds, by C1, I7 and B1.
- *Recurrence*, the conference-room "recurring instance", is not modelled.
- *One language.* Only the Python reference exists; the ladder's re-tell
  fan-out has not been done.
- *This cell ships only =python3.12=, with no =python3=.* The ladder's own
  =run.sh= files call =python3=, so the root gate reports FAIL=9 here (FAIL=5 at v2.4.0) for that
  reason alone. With a =python3 -> python3.12= PATH shim it is PASS=9 on
  origin/main. This experiment's =run.sh= falls back to =python3.12=.
